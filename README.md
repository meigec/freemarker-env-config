# freemarker-env-config

[![ci](https://github.com/meigec/freemarker-env-config/actions/workflows/ci.yml/badge.svg)](https://github.com/meigec/freemarker-env-config/actions/workflows/ci.yml)

Learning proof of concept by **Eduardo García Meier**: **one set of FreeMarker (FTL) templates, versioned in Git, generates the configuration for every client and every environment**, with tests that enforce the rules and a CI pipeline that renders everything on each push.

This is the pattern behind "plan and code templates stored in Git alongside application code": template changes are version-controlled, code-reviewed and tracked, and environments stay standardized and reproducible.

## Why I built this

FreeMarker was new to me. My daily templating has been Helm and Terraform `templatefile()`. Rather than just reading the documentation, I built a small but complete example to learn the principles hands-on and connect them to what I already know: layered values, environment rules, reusable blocks, secrets kept out of rendered files, tests and CI. It is a learning project, not a claim of expertise, and the comparison table at the end maps each FreeMarker concept to its Helm and Terraform equivalent.

## What it proves

| Capability | How it is shown |
|---|---|
| **One template, many environments** | 2 clients × 3 environments (dev, staging, prod) × 2 templates = **12 generated files** from a single template set |
| **Layered configuration** | `defaults → client → environment → client/environment override`, deep-merged (later layers win) |
| **Environment rules in templates** | Production gets 3 replicas, `WARN` logging and no debug endpoints, decided by `<#if>` on the environment tier |
| **Exceptions without forking** | `overrides/globex-capital-prod.yaml` changes one feature flag for one client in one environment only |
| **Secrets never rendered** | Templates emit references (`sm://<client>-<env>/db-password`) resolved at runtime by a secret manager; a test fails if a literal value ever appears |
| **Fail fast** | A missing required value breaks the build instead of producing a broken config |
| **TDD** | Tests describe the rules first (replicas, defaults, overrides, merge order, secrets, valid Kubernetes YAML) |
| **CI** | GitHub Actions runs the tests, renders all combinations and publishes them as an artifact |

## FreeMarker features used

| Syntax | Where | Purpose |
|---|---|---|
| `${app.name}` | everywhere | interpolation |
| `${app.logLevel!"INFO"}` | both templates | default when a layer does not define the value (staging) |
| `${app.replicas?c}` | both templates | computer-format numbers (no locale separators) |
| `<#if env.tier == "production">` | `application.properties.ftl` | environment-specific rules |
| `<#list services as svc>` | both templates | one entry per service |
| `<#list app.featureFlags as flag, enabled>` | `application.properties.ftl` | key/value iteration over a map |
| `<#macro>` / `<#function>` | `lib/macros.ftl` | reusable header, service URLs, secret references |
| `<#import "lib/macros.ftl" as m>` | both templates | shared library in its own namespace |
| `?upper_case` | `configmap.yaml.ftl` | built-ins to transform values |

## Structure

```
data/
├── defaults.yaml              # shared by everyone
├── clients/                   # one file per client
├── environments/              # dev, staging, prod
└── overrides/                 # optional client+environment exceptions
templates/
├── application.properties.ftl
├── configmap.yaml.ftl         # Kubernetes ConfigMap
└── lib/macros.ftl
src/main/java/.../Renderer.java    # loads YAML layers, merges them, renders every template
src/test/java/.../RendererTest.java
.github/workflows/ci.yml
```

## Run it

Requires Java 21 and Maven.

```bash
mvn verify          # run the tests
mvn -q exec:java    # render everything into out/<client>/<environment>/
```

Example output, `out/acme-bank/prod/application.properties`:

```properties
# application.properties: generated by FreeMarker from Git-versioned templates. DO NOT EDIT.
# client=acme-bank environment=prod
app.name=trade-gateway
app.client=Acme Bank
app.environment=prod
app.log.level=WARN
app.replicas=3
app.debug.endpoints=false
...
db.password=sm://acme-bank-prod/db-password
```

## If you know Helm or Terraform

| Concept | Helm | Terraform | This POC |
|---|---|---|---|
| Template | `templates/*.yaml` | `templatefile()` | `templates/*.ftl` |
| Values | `values.yaml` + `values-prod.yaml` | `*.tfvars` per environment | `data/` layers |
| Default value | `{{ .Values.x \| default "y" }}` | `try(var.x, "y")` | `${x!"y"}` |
| Loop | `{{ range }}` | `for` expressions | `<#list>` |
| Reusable block | `_helpers.tpl` | modules | `<#macro>` / `<#function>` |
